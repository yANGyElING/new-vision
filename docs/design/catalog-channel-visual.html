Catalog 与通道模型 —— 可视化理解确认

四个确认点：A 数据流向 / B 字段权威 / C 通道生命周期 / D 权限跟随。哪块不对，指哪块。

A数据怎么流：通道只从设备来

确认 A：通道数据的唯一来源是设备上报；方向是 access → app（上行），不走现有 outbox。

B一行通道数据，谁说了算

字段示例值设备能写?平台能写?
channel_code34020000001320000001身份锚点，谁都不改
report_name（设备名）"Channel 01"✓ 每次同步刷新✗
display_name（平台名）"大门口"✗ 永远冲不掉✓ 老张小李小陈维护
org_unit_idNULL = 跟随设备✗✓（初期 UI 不做）
reported_statusON / OFF✓ 每次同步刷新✗ 只读
missingfalse同步结果自动驱动（见 C）

界面显示的名字 = COALESCE(display_name, report_name) → "大门口"
运维小哥在 NVR 上把通道改成 "Channel 01"，老张在平台备注的名字纹丝不动。

确认 B：设备上报只能写 report_name / reported_status 两列，其余列它碰不到；字段缺省时保留旧值，不清空。

C通道的三种活法（永不删除）

确认 C：「离线」= 设备还承认这路但它掉了；「缺失」= 设备不再承认这路。缺失只认完整同步；恢复出厂变码 = 断链，接受。

D权限自动跟随：新通道开箱即在管辖内

确认 D：新通道 org_unit_id 一律 NULL（跟随设备）；设备换组织，通道自动跟着走（COALESCE 天然成立）。
